## Observed limits and next-stage gates

- Chromium's tested upstream build can retain a `Crashed` exit marker and show a restore prompt after signal-based shutdown. The broker disables the upstream restart watchdog and signals the main Chromium process before Docker stop, allowing profile flush. Actual profiles/history were retained; a completely clean Chromium exit marker was not established. Ordinary session cookies should not be treated as guaranteed persistent cookies.
- The host initially had IPv4 forwarding disabled. Docker enabled it when creating the project bridge; it later reverted while V2rayA's core had restarted. The resetting component was not identified. The user explicitly approved enabling runtime `net.ipv4.ip_forward=1`. No persistent sysctl file was changed. Coordinate a durable solution with the existing networking setup before deployment.
- Existing HomeCloud containers were inspected and left running. Existing Caddy/FRP/SSH configuration was not edited or reloaded. Selected non-secret FRP routing fields were later inspected through a read-only Docker mount; the existing routes are recorded in the deployment guide. VPS-side Caddy/FRPS still requires review. Docker necessarily created its own project networks and firewall rules; there was no manual firewall-rule edit.
- Disposable browser containers, networks, profile volumes, accounts and generated credentials were removed after acceptance. The localhost deployment was reset to an empty account database so the owner can initialize `thatyt` with a private password.
- The temporary `thatyt` Docker-socket ACL was removed after testing. The root-owned orchestration broker remains functional; operator Docker commands now require sudo or another authorized Docker context. Runtime IPv4 forwarding remains enabled as explicitly approved.
- No public ports, public DNS changes, GitHub push or production deployment were performed. The standalone development Caddy is separate from the existing service.
- Before internet exposure, complete `docs/DEPLOYMENT.md`: deny the real host/VPS public management addresses, inspect FRP and TLS/proxy trust boundaries, test external reachability and DNS-rebinding/alternate-transport cases, scan the upstream image, review host/kernel isolation, verify backup restores, and test physical clients. Upstream launches Chromium with `--no-sandbox`; containers are not VM isolation for hostile tenants.
